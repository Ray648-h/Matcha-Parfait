一、初识GitHub：它到底是什么？
 
在没接触GitHub之前，我一直以为它只是个“代码存储网站”，真正学习后才明白，GitHub是基于Git的分布式版本控制平台，核心作用远不止存代码：
 
- 版本管理：记录代码每一次修改，随时回退到历史版本，再也不怕改坏代码找不到原版
- 协作开发：多人共同写项目，各自修改后合并代码，高效完成团队作业
- 开源共享：发布自己的项目，学习他人优秀开源代码，参与开源社区
- 作品集展示：把自己的项目托管到GitHub，求职时能直接展示编程成果
 
对于新手而言，先不用纠结复杂的分布式原理，重点掌握本地代码与远程仓库同步的基础操作即可。
 
二、前期准备：注册账号+安装Git
 
1. 注册GitHub账号
 
直接访问GitHub官网，用邮箱注册即可，注意用户名尽量简洁好记，后续会作为仓库地址的一部分。注册完成后，完善个人资料，新手阶段不用设置复杂权限，默认配置就够用。
 
2. 安装Git工具
 
GitHub的核心操作依赖Git命令行，Windows、Mac、Linux系统都需提前安装：
 
- Windows：访问Git官网下载安装包，一路默认安装即可
- Mac：可通过Homebrew安装 brew install git ，或直接下载安装包
- 安装完成后，打开终端/命令提示符，输入 git --version ，显示版本号即安装成功

四、新手必学的基础操作技巧
 
1. README.md文件的作用
 
每个仓库都建议有README.md，它是仓库的“说明书”，用Markdown语法编写，可写项目介绍、使用方法、安装步骤，别人看到你的仓库，首先看README，新手简单写清楚项目用途即可。
 
2. 常用Git命令速记
 
命令 作用 
git init 本地初始化新仓库（不克隆远程，直接新建本地仓库时用） 
git add 文件名 添加单个文件到暂存区 
git commit -m "说明" 提交到本地仓库 
git push 推送到远程 
git pull 拉取远程最新代码 
git log 查看提交历史记录 
git status 查看文件修改状态

五、新手踩坑避坑总结
 
学习过程中踩了很多低级坑，整理出来帮大家少走弯路：
 
1. 用户名邮箱配置错误：第一次提交时报错，大概率是邮箱和GitHub不一致，重新用 git config --global 修改即可
2. 文件名用中文：Git对中文支持不友好，仓库名、文件名尽量用英文，否则会出现乱码
3. 忘记git add直接commit：commit前必须先add，否则修改的文件不会被提交
4. 网络问题导致push失败：国内网络偶尔会连接GitHub失败，可切换网络，或耐心重试
5. 直接在网页端和本地同时修改：两边修改后不pull直接push，会出现冲突，修改前先pull，保证版本一致
 
六、学习感悟与后续进阶方向
 
经过这段时间的学习，我彻底摆脱了“只会本地写代码，不会版本管理”的困境，GitHub不仅是代码托管工具，更是编程学习的必备技能。
 
新手阶段不用急于学复杂的分支管理、PR合并、开源贡献，先把克隆、提交、推送、拉取这四个基础操作练熟，养成用Git管理代码的习惯。后续进阶可以学习：
 
- 分支管理（git branch、git checkout）：开发新功能时不影响主代码
- Pull Request：参与开源项目，提交自己的代码修改
- GitHub Pages：搭建个人博客/项目展示页面
